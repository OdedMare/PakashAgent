# Q: אני כן רוצה שיהיה חיבוריות לagent שיריץ ויראה ויקבל החלטות

## Answer

Expanded from original query via vocab: [agent, scheduler, generation, preview, decision, proposal, confirm, apply, audit, tools, rotation, triplet]. The generate_day request now stays in the proposal-confirm flow: ScheduleService builds several deterministic audited candidates, ChangeAgent.decide_day sends their exact assignments, workload, warnings and notes to the bounded fast schedule_decision model, and the chosen candidate is embedded in the proposal. On confirmation, ScheduleService regenerates the legal candidates from current data and persists only when the preview signature exactly matches one of them; otherwise it requests a fresh proposal. Rotation and triplet configuration remain mandatory in deterministic generation and at write boundaries. If the decision model is unavailable or exceeds its 20-second ceiling, candidate zero is used so core generation still works.
